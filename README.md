# Yui · 灰玻璃小手机

SillyTavern / TauriTavern 扩展，**0.15.0 · 补记修改与长聊天**。

## 0.15.0 · 补记修改与长聊天

沿用 0.14.0 的开关和 **content,yui_phone** 配置。正文生成前只追加尚未同步的新消息，已同步的历史保留在手机，不重复追加。

- **逐条双向修改**：开启补记总开关后，手机编辑/删除会同步到当前所选正文备选中的对应补记；楼层小铅笔编辑补记“内容”下的文字并保存，也会更新手机。清空该条内容或删除该条完整的消息标记块会真正删除手机消息。请保留发送者、时间、引用及其他标记；表情包与转账仅支持从楼层删除，收款/退款在手机内操作。
- 每条消息用稳定 ID 对应，即使文字一样也不会误改邻近消息。只更新当前备选，其他备选保留；手机历史不随切换备选自动回滚。切换后先核对再继续。
- 两边同时改了同一条、楼层保存未确认或标记损坏时停止同步，显示“补记同步待核对”。可到设置 → 待同步补记核对并重试。已同步消息记录独立保存，整楼删除后也不会作为新消息再次追加。
- **整块删除单独处理**：整块补记被移除时保留手机消息；在待同步补记点“保留手机记录，解除已删除补记的关联”确认后继续。它只解除已经整块移除的关联，不批量清空手机历史。
- **聊天默认显示最近 50 条真实消息**，可点“查看更早消息”逐批展开。AI 参考条数仍按独立 API 设置的历史条数计算（默认 40），与屏幕显示数量分开。
- 聊天顶部的紧凑提示可展开查看原始对话参考范围、未同步数量和存储容量。超过回复参考范围时提示较早记录没有作为原文发送；接近本机容量上限时提醒。达到保存或补记上限会明确停止，不自动丢消息。
- **千千结总结状态未确认**：写入正文不等于千千结已完成总结。已有摘要不随消息编辑/删除自动重写；是否记住较早聊天仍取决于千千结配置与实际结果。本批没有增加副 API、自动小结或二次总结。
- 旧版补记仅在原内容与手机记录完全一致时自动建立逐条关联；已经被修改或来源缺失的旧块需先核对。不能为升级前已经删掉的正文恢复对应关系。

下面保留各版说明；涉及编辑和删除的旧限制以本节为准。

## 0.14.0 · 剧情时间与手机补记

1. 设置 → **剧情时间**：默认读取当前存档最新 AI 正文的结束时间标记（QQJ / SDC / myknots）。包含有正文的隐藏楼层，只取当前备选；缺失时沿用同存档此前已确认时间，标记冲突或没有时间时明确显示。也可选设备时间或手动校正；新正文出现后手动校正失效。等待不会自动推进剧情时间。
2. 新手机消息记录发送时的剧情时间，手机 AI 参考也包含当前时间；旧消息仍显示原设备记录时间，不补造历史时间。剧情时间为存档级设置，与按人物读取剧情全文的开关分开；关闭人物全文参考不会阻止手机时钟读取时间标记。
3. 人物资料 → 剧情衔接 → 勾选 **将此人的手机聊天提供给正文**，保存人物；再到设置 → **待同步补记**，预览内容、开启 **保存手机补记到正文**并保存。总开关默认关闭，首次启用会列出此前尚未同步的该人物消息，可取消不需要的记录。
4. 正常点击酒馆生成时，先把所选新手机消息追加到**上一条 AI 正文末尾**并保存读回，再继续发言/生成。独立的 `<yui_phone>` 包裹，不增加 user 楼；已有用户发言保留。显示为可展开的“手机交流 · N 条”。当前备选回复及其 extra 一并更新，其他备选不改。
5. 千千结设置 → 通用设置 → 提示词与包裹符 → **保留包裹符**，在原有项目中追加 `yui_phone`；原来只有 content 时填 **`content,yui_phone`**。清洗包裹符可继续保留 `status_board,options,section`，不要将 yui_phone 填入清洗项。摘要内容指导不必改。补记在 MESSAGE_SENT 前保存；千千结按其自身设置总结 AI 楼。独立的 summary/记忆写回 API 未调用。
6. 补记保留参与者、先后顺序、已记录的剧情时间、引用、表情包说明及转账状态；仅有权知情者可依据交流。每人每批最多条数沿用人物设置（1–200）；整批上限 4 万字符，超限提示选择内容，不静默截断。
7. 保存失败或读回未确认会保留待处理状态、停止正文请求；可到待同步补记点“核对并重试补记”。保存结果不明时先读回确认，避免重复追加。已同步消息通过楼层 extra 回执及正文内容共同核对；被手动改动的补记不会自动覆盖。

### 本批范围

- 支持 ST 角色聊天及具备 history.tail 的 TT 角色聊天；宿主群聊暂未开放。正文需要完整加载才能检查同步记录。
- 仅正常生成追加新补记；静默请求、代答、重生成、滑动备选、续写和自动触发不追加。没有上一条 AI 正文时明确提示。
- 已保存补记不会随手机编辑、删除自动改写；已有摘要不自动重做。剧情分支/回退不提供完整同步，切分支后请先核对待同步列表。以上仍属第二批讨论范围。
- 手机自动小结、二次总结和副 API 尚未实现。当前发送的是选中的原始记录，不能宣称无限历史或自动节省 token。
- 写入前后核对当前存档及正文，ST 网络请求有超时；同时编辑同一存档的多个设备/窗口没有数据库级事务保证。请避免并行改同一份正文。
- 浏览器与宿主契约模拟通过，千千结实际过滤函数通过；真实 ST/TT、用户安装的千千结版本及真机时序仍需验收。

## 0.13.0 · 千千结记忆读取

人物资料 → **记忆 · 千千结** → 打开“参考千千结记忆”，选择参考内容，预览后保存人物。默认关闭，按当前手机存档、人物分别保存。

- “剧情记忆”读取千千结最近为当前正文准备的前情和召回材料，不会针对手机消息重新检索；材料中可能已经包含千千结选中的人物状态。没有快照时明确提示，不自动读取整个记忆库或触发正文生成。
- “人物档案 / 人物状态”只读取明确绑定的千千结人物。开启联动会加载已准备好的人物选项，也可点“刷新人物”；同名人物按稳定 ID 区分，不自动猜测。仅选剧情记忆可不绑定人物。状态保留本人私密、作者参考等知情范围与依据；部分结果标明覆盖不完整。
- “预览本次记忆”与实际回复共用读取函数；设置 → 聊天预设的完整发送预览也包含这份参考。只读取，不调用 AI。实际回复前重新核对，生成期间记忆变化会取消迟到回复。
- 字数上限默认 12000，可设 1000–30000，按字符计数，不等同于 token。超限停止请求并提示调整，不自动截断正文或知情边界；整个手机请求继续受原 18 万字符上限约束。
- 插件未安装、未启用、接口过旧、当前存档未就绪或所选材料为空时明确报错。可关闭此人物联动继续聊天。复制或重建存档导致千千结 UUID 变化时需点“关联当前存档”，重新选择人物并保存；不会沿用上一份存档的记忆。
- 手机只持久化开关、存档/人物绑定及上限，不存储千千结记忆副本，不修改插件记录。调用的是 v1 公开只读接口，不调用后台全库读取或总结接口。
- 本版先接入已有记忆读取；手机聊天自动小结、二次总结、副 API 和写回千千结尚未实现。现有“参考酒馆正文”开关独立保留，同时开启可能有信息重叠，可减少原文条数；不宣称自动去重。
- Chrome / WebKit 的 ST/TT 模拟通过；实际安装的千千结版本、真实 ST/TT 和 iOS 手感仍待用户验收。

## 0.12.0 · 聊天预设

手机桌面 → 设置 → **聊天预设**。API 地址、密钥与模型仍在“独立 API 设置”。

1. 选择“Yui 默认”，点“复制预设”后编辑；也可新建或导入 JSON。修改预设名字，添加、编辑、开关、删除文字条目，用“上移 / 下移”调整顺序。内置默认只读；自定义条目可选系统提示、用户消息或角色示例。
2. “使用此预设”选定要用的预设，点 **保存预设设置** 后生效；查看其他预设不会自动切换。取消未保存修改可恢复；离开和更新刷新会保护草稿。删除当前使用的预设需先选替代预设，保存后从预设库移除。
3. “固定资料与功能”由程序提供人物资料、世界书、正文参考、手机历史与功能规则，不可移动、删除或关闭。人物正文读取及世界书条目仍由人物资料控制，导入预设不会替你打开。
4. **预览本次发送内容**：读取当前存档好友，选择一人后预览。使用当前查看的预设草稿；展示实际参考、会话和系统规则，不调用 AI。保存并使用同一预设后，在资料和历史未变化的情况下，实际请求与预览一致。
5. 原先 API 设置里的前置、风格自定义文字会显示为“原有提示词”，顺序和内容保留。保存预设前仍沿用旧文本；不删除或改写原 API 设置。首次没有自定义文本则使用 Yui 默认。

### 导入与存储

- 支持 Yui v1 JSON 和具有真实文字条目的线上 nuopreset；先显示兼容检查，确认后作为新预设加入，最后保存。不支持直接导入酒馆完整 API 预设。
- 用户提供的“內建默認 ✦.nuopreset.json”主要是原手机的 marker，占位项不带内置提示词正文。format 使用 Yui 自己的功能协议，其余未映射项单独列出且不发送给 AI；导入不代表原手机的记忆、日程等功能已实现。
- 附带正则不执行、模型参数不覆盖 API。支持 {{user}} / {{char}} 名字替换；其他未知变量和不支持的深度位置保留文字但关闭，需编辑确认后手动开启。重复条目 ID 会重新分配，不合并内容。导出不带 API 配置、人物资料或聊天历史。
- 每个文件最多 1 MB，每库 30 个预设，每预设 80 个文字条目、20 万字符，每条 12000 字符。无效格式、容量和已发现的多窗口修改会停止保存并保留草稿，不自动清理。
- 预设保存在本设备、同一宿主来源的 localStorage：yui-glass-phone.presets.v1，另保留上一次保存前的 .backup。它沿用本机 API 的设置范围，不按人物或宿主账号分库；不同来源、设备间不自动同步。单份上一版本不是完整备份，可用导出另存。
- 生成期间更换已保存预设，会丢弃迟到回复并提示重新请求，不让旧回复进入新的设置流程。未提交消息、人物资料与素材存储不改。

### 剧情表达与配套文件

- 给模型的转账规则按**故事中实际发生的交易**表达，以待收款、已收款、已退回状态为准，不把待收款说成到账，不编造余额。应用本身没有真实支付接口。
- 聊天风格改由预设管理，不再提供此前未发布的线上规则世界书。可导入的默认预设、可选正文补充书和显示正则见 [配套说明](extras/README.md)。
- 可选正文世界书仍是静态规则。Yui 由插件直接提供已授权手机交流，没有注册自定义世界书变量；给书改名或写一个占位符都不会接通动态数据。
- 按用户的新要求，开启人物正文读取后，**有正文的隐藏楼层也会带入**，计入最近 N 条；预览显示隐藏数量。工具及明确标记的插件内部消息跳过，只使用当前已加载聊天和当前备选。已开启的旧人物也采用此规则，不自动补读整个宿主历史。
- 正文参考采用自己的完整区块标记；正则仅隐藏误回显的完整区块。读取正文时也过滤该区块，宿主原文不删除。没有新增正文消息解析、分支回滚或全局宏替换。
- 0.12.0 已发布到 GitHub main。运行入口仍为 manifest 指定的 index.js 和原生 ES modules。真实 TT/ST 新功能均待验收；基础通讯录仍仅记录“用户在 TT 实测通过”。

## 0.11.0：手机与正文的剧情衔接（历史说明；提示词入口与隐藏规则以 0.12.0 为准）

### 提示词放在哪里

手机桌面 → 设置 → **独立 API 设置**：

- **前置提示词（选填）**：留空不插入；填写后作为手机回复请求的第一条 system 消息。最多 12000 字符，仅用于独立手机 API，不改酒馆预设。排在最前面不代表能绕过接口或模型自身限制。
- **聊天风格提示词**：可修改语气、表达、回复长短等。每个人的线上习惯仍放在人物资料的“线上人设”。
- 表情包、转账、收退款等内部功能协议由程序附加，不在风格编辑框中显示。原封不动的旧默认文案会换成新的风格默认值；用户自定义文本保留。
- 实际顺序：前置提示词（如有）→ 聊天风格 → 内部功能规则 → 来源角色卡、线上人设、当前酒馆用户人设、我的名片名字、勾选世界书和可选正文 → 当前手机会话 → 回复要求。获准的表情包描述和待处理转账信息继续由内部协议附加。图片字节不发送，尚无识图。

手机请求仍直接走单独配置的 API，不经过酒馆的正文生成端点，所以不保证出现在酒馆服务端日志中。以下两个剧情方向分开控制。

### 每个人单独选择

人物资料 → **剧情衔接**，修改后点“保存人物”：

1. **参考当前酒馆剧情**：默认关闭；开启后选择最近 1–100 条可见正文（默认 10）。先排除隐藏楼层、系统/工具记录、空消息再计数；仅使用当前已加载聊天的当前备选内容。不读取隐藏内容、其他聊天或其他备选回复。每条最多 10000 字符、合计 30000 字符；预览显示实际条数与截短提示。无法确认隐藏状态时停止请求，不猜测为可见。
2. **将此人的手机聊天提供给正文**：默认关闭；可选最近 1–200 条已保存手机消息（默认 20）。只分享本存档中启用此项的现有好友；未发送草稿、待确认消息、已删除人物不带入。正文生成时临时添加扩展参考，结束、停止、切档、编辑/切换正文时清理，不新增可见楼层、不修改正文存档或预设。
3. 两个“预览”按钮只展示准备参考的文本，不调用 AI；实际生成时会重新读取和核对。NPC 可保持全部关闭，也可单独开启其中一个方向。

## 安装与使用

1. 酒馆扩展管理 → 从 URL 安装：`https://github.com/yui-ovo/yui-glass-phone`。
2. 安装后刷新，打开一个有效聊天，点击屏幕边上的圆形手机图标。
3. 手机「联系人 → 右上角 +」可从当前卡带入或手动创建人物。角色卡标题可改成人物真名，同一存档可登记多人。
4. 选择开局关系并保存。只有「已是好友」的人出现在联系人；「联系人 → ⋯ → 管理剧情人物」查看所有登记人物。
5. 打开好友聊天，输入文字并点发送。Enter 换行，不触发发送；右上角 ⋯ 编辑资料。「我 → 我的名片」设置自己的名字和头像。

没有有效聊天或无法确认宿主账号时，会提示重新打开/读取，不建立共享备用通讯录。无需同时启用旧手机、酒馆助手或任何 AI 插件。

## 本轮已接入

- 人物名字、备注、线上人设、来源角色卡、独立人物 ID、固定虚构账号。
- 三种关系：已是好友、认识但未加好友、尚不认识。登记人物不会自动加好友。
- 头像本地上传（PNG/JPEG/WebP，2 MB 内，4096×4096 内，缩至最长边 512）或明确加载 HTTP(S) URL。失败保留原头像。
- 我的名片和固定虚构账号；账号在首次保存后固定，本轮不做账号搜索/修改。
- 按当前账号/角色来源/聊天保存，刷新恢复，切档隔离。切换聊天会取消旧页面尚未保存的草稿。
- 保存失败保留当前草稿；「取消」不保存；收起手机后再打开仍保留当前编辑内容。
- 保留已关联世界书资料；人物资料中可打开指定世界书、添加条目快照并勾选/排除。
- 真实模式与独立样式演示分开。用户文字与明确请求的 AI 文字回复保存到同一会话。

## 独立 API 与回复用法（0.6.0 起，剧情参考见 0.11.0）

1. 手机桌面「设置 → 独立 API 设置」，填写 API 地址、密钥和模型。地址填写到接口前缀，例如 https://example.com/v1；程序追加 /models 或 /chat/completions。支持兼容 OpenAI 的 Bearer 鉴权、非流式文字聊天接口；不是直接填写网页地址，也不支持原生 Claude/Gemini 协议。
2. 可获取模型列表或手动填写模型名称。「测试连接」只发送简短测试文字，可能产生接口费用，不携带人物资料。高级设置可改温度、输出长度、最近手机消息条数和等待时间（默认 120 秒，可设 30–600 秒）；点击保存后用于回复。
3. 「联系人 → ⋯ → 管理剧情人物 → 人物」，确认名字、线上人设和好友关系。在「AI 回复参考 · 世界书」先读取书名，再打开指定书，逐条添加参考。上方勾选框可排除无关内容。点击「保存人物」生效，取消不保存。
4. 聊天输入框有非空白文字时，飞机仅保存用户文字；空白时再点飞机才请求对方回复。发送成功后有 800ms 防误触间隔。请求中灵动岛播放三个小点动画，点击灵动岛可停止本次请求，飞机也保留停止操作；Enter 始终换行，不触发发送或 AI。
5. 生成成功后自动保存一条对方文字气泡。保存未确认时保留临时气泡，点击「核对并重试」仅按原消息 ID 补存，不再次请求 AI。返回列表可看最新摘要，刷新后可检查已保存的双方消息。

回复参考：人物来源角色卡的名字/描述/性格/场景/示例对话、线上人设、当前酒馆正在使用的用户人设名字与描述、手机名片名字、已勾选的世界书快照及当前手机会话最近 N 条（默认 40）。不遍历其他用户人设，不读取全账号聊天、预设或宿主 API 密钥。0.11.0 起可按人物开启读取当前可见正文，默认关闭。来源卡找不到、没有完整加载，或无法取得当前用户人设时停止并提示。手动人物使用人物资料和线上人设，不自动套用另一张卡。

「我的名片」仍是手机内独立昵称、头像与虚构账号。在名片编辑页可以明确点击「带入当前酒馆人设的名字和头像」，预览并保存；不会改写酒馆人设或重建手机账号。AI 每次读取当前选中的酒馆人设，手机名片不会随人设切换而自动被覆盖。

世界书只在点击后读取所选书，不自动扫全书库。已添加内容保存为原 roleplayMaterials 快照；取消勾选只增加人物的 aiExcludedMaterials 排除项，不删除原条目。相同书名与 UID 不重复添加，不默默覆盖旧快照。最多 20 条、总计 4 万字符，超限提示。书中的禁用条目会标明，只有手动明确添加才会参考。本版不会跟随原书的自动触发条件或内容变更。

### 网络、存储与取消边界

- API 配置与密钥存于当前设备同源 localStorage 的 yui-glass-phone.ai.v1，独立于外观和酒馆 API 配置；同一站点的酒馆账号共享此项。密钥以本机明文存储、页面密码框遮盖，不是系统钥匙串；不随人物或消息保存，也不提交仓库。
- ST/TT 均使用显式配置地址的浏览器 fetch，请求不携带酒馆 cookies，不跟随重定向。服务须允许浏览器跨域，HTTPS 酒馆需使用 HTTPS API。没有借用仅适用于 ST 的服务端生成端点，也没有使用 TT 私有 invoke。真实 TT 2.3.0/iOS 17.5.1 网络能力及各接口兼容性待实测。
- 请求超时、格式不符、输出截断或返回工具调用会提示并停止，不把残缺内容当作完整回复保存。没有工具执行、HTML 执行或自动斜杠命令。API 可读参考总量上限为 18 万字符，超过时提示减少条目/历史条数。
- 切换联系人、返回其他页面、收起手机或禁用扩展会取消正在等待的 AI 请求；已发出的请求仍可能被服务商计费。切档取消草稿并提示。迟到结果不会插入新会话。原生消息写入已经发出时仍绑定原存档，不能撤回。
- 请求期间当前人设/人物参考资料或手机会话改变时，停止保存这次回复并提示。正在请求、未保存配置/人物修改/消息草稿、未确认保存的气泡均参与版本刷新保护。刷新或退出可能丢失尚未保存的内存内容。
- AI 与用户消息使用下面相同的独立消息存储，不写入宿主正文。没有新增备份、跨设备同步或分支对齐；TT 原生存储的备份行为尚未验证。

## 文字消息使用与存储

- 输入中文、多行和 emoji，点发送保存；每条最多 10,000 个 Unicode 字符，空白不提交。只对已是好友的本存档人物开放。
- 气泡沿用用户提供的正则手机 cv2 样式。我方头像取自本存档「我的名片」，对方头像取自人物资料；不在气泡上显示姓名。内容只按文字显示，不执行 HTML 或斜杠命令。
- 发送中标为「尚未确认保存」；失败保留原文与同一个消息 ID，点「核对并重试」。TT 报错不代表绝对没写入，重试会先核对原存档是否已有该 ID。
- 返回列表/切换手机联系人/收起手机保留各会话未发送草稿；切换剧情存档会明确取消旧草稿。草稿仅在本次页面内存中，未保存草稿/未确认操作会阻止版本自动刷新。手动强制刷新仍可能丢失未保存内容。
- 消息列表按最新已保存消息的顺序排列，摘要从同一份记录派生，没有假未读/已读/送达。气泡时间是设备记录时间，不代表剧情时间。
- 同一操作快速连点或失败重试不重复；用户成功发送后再发相同文字会产生另一条消息。

消息与人物分别存储，不更换通讯录 UUID、不重建 self。本人引用为固定的 `self:<通讯录 UUID>`，手机会话以人物 UUID 关联，改备注不会创建新会话。

**ST 消息**：同源 localStorage 的 `yui-glass-phone.messages.v1:<账号>:<通讯录 UUID>`。**TT 消息**：原公开 chat store 中独立 `messages-v1-<聊天文件名 SHA-256>`，namespace 仍是 `yui-glass-phone`。人物资料位置保持原样。

每份消息文档含版本、存档 ID、revision 和唯一 messages 数组；每条含版本、messageId、archiveId、conversationId、发送者/接收者稳定引用、正文、createdAt、sequence、source（phone-manual 或 ai-reply）。旧的用户文字记录无需迁移；AI 记录使用人物→self 的引用方向。仍不接受或伪造正文楼层和分支标识。0.5.x 不支持 AI 来源，已有 AI 记录时回退会停止读取消息，不应通过清空历史解决。

消息写入使用浏览器 Web Locks 串行处理同源协作窗口，并核对 revision；不支持锁时停止消息写入并提示，通讯录仍可用。发现较新消息时拒绝覆盖，先「重新读取消息」，再按原 ID 重试。不能承诺跨应用进程/设备的原子事务，TT 原生 store 没有条件写入 API。

本版每存档最多 2,000 条现存消息、合计 1,000,000 个 UTF-16 单位正文；容量/格式错误停止写入，不自动删除或截断历史。记录格式错误时也不会用空历史覆盖。

### 备份与分支边界

没有新增导出/备份或跨设备同步。ST 浏览器数据不随聊天导出；清理站点数据会删除这些本机记录。TT 消息属于宿主独立扩展存储，其备份/导出行为尚未验证。

同卡不同聊天继续独立；复制档即使保留 integrity 也使用不同文件名键。没有实现继承消息、分支回退、合并、重新生成对齐或跨存档搬运，不把这些项目标为通过。原生写入发出后可能在切档后完成，但只绑定原存档。

## 数据存在哪里

**ST**：同源只读 `/api/users/me` 确认账号；写入浏览器 `yui-glass-phone.contacts.v1:<编码后的账号>`，内部按来源文件/群组、聊天名和可用 integrity 区分。人物自身使用 UUID，名字、备注、角色数组下标不作永久 ID。

**TT**：等待公开 ready，使用 `api.chat.open(ref).store`；namespace 为 `yui-glass-phone`，key 为 `contacts-v1-<聊天文件名 SHA-256>`。不请求 ST 账号端点，不使用私有 invoke。原生写入一旦发出无法撤回，但始终绑定原聊天。

只持久化新手机资料，不读写旧 `yui-pocket` 命名空间，不调用宿主聊天/metadata 保存接口，不扫描账号全部聊天。开启剧情参考时，只读取当前已加载的可见正文或临时提供选定的手机交流。无法读取或资料损坏时停止保存，避免拿空资料覆盖。现有世界书字段与未知扩展字段通过整份复制保留。

ST 浏览器资料不会自动跨设备或随聊天导出；TT 的导出/备份随宿主行为，尚未真机验证。并发修改有 revision 冲突检查，但不承诺跨窗口原子事务。

**本版未实现旧用户资料导入。** 代码复用不等于搬运旧资料。后续导入必须先确认当前存档身份、显示范围、保留备份并确认复制，重复执行不得重复录入。旧仓库与旧资料保持不变。

## 更新、草稿和生命周期

扩展管理中更新本项目后，点击「关闭」会检查本地 manifest；版本改变且没有未保存草稿/进行中的操作时才刷新。有草稿会暂缓，保存/取消人物修改、发送/清空消息草稿并处理未确认消息后，再次打开并关闭扩展管理器即可重试。首次加载本版前仍运行旧版逻辑。

重复启用只保留一部手机；提供 activate/enable/disable/delete 清理 hook。宿主事件、布局订阅、更新检查、计时器和图片操作都有退出清理；不支持 hook 的宿主沿用其正常刷新卸载流程。真实 ST/TT 的更新和生命周期行为仍待用户验收。

## 尚未实现

## 开发和验证

`manifest.json` 继续加载 `index.js`，所有 `modules/*.js`、`update-refresh.js` 和 `style.css` 必须一起发布。运行代码是原生 ES modules，**无需构建**，没有运行时 npm 依赖。

静态服务器打开 `preview.html` 可看外壳；通讯录需要有效宿主，独立预览时用设置里的样式演示入口。
